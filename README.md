# TimeLabs

Автономное настольное приложение для школьного расписания. Python 3.12, PySide6,
SQLite, OR-Tools CP-SAT. Русский интерфейс. Для работы приложения не нужны браузер,
HTTP-сервер, Docker, облако и интернет.

**Версия 0.2 — рабочая начальная реализация, ещё не полное выполнение ТЗ v1.1.**
Реализованные возможности и ограничения перечислены в [docs/STATUS.md](docs/STATUS.md).
Демонстрационная школа вымышлена. Для переданной уточнённой книги и DOCX кабинетов
добавлен [режим сверки школьных исходников](docs/SCHOOL_IMPORT.md); персональные
данные не включены в исходный код.

## Запуск из исходников

Windows 11 x64, установлен Python 3.12 x64:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.lock
.venv\Scripts\python.exe -m timelabs.ui
```

После первоначальной установки повторный запуск: `scripts\run-windows.cmd`.
Только установка зависимостей требует сети. При первом запуске создайте свой логин
администратора и пароль от 10 символов. Предустановленных паролей нет.

Linux (для разработки, не заменяет приёмку Windows):

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m timelabs.ui
```

## Первый рабочий сценарий

1. В меню «Проект» можно загрузить **демонстрационный пример**. Это заменяет текущий
   проект после подтверждения и резервной копии. Для реальной школы начните со
   «Справочники и правила»: предметы, кабинеты, учителя, классы и группы.
2. Для класса и каждой подгруппы задайте обезличенные коды состава. Например, весь
   класс `p01,p02,p03,p04`, первая группа `p01,p02`, вторая `p03,p04`. Пересекающиеся
   группы используют общие коды. Не нужны настоящие ФИО учеников.
3. В режиме «Базовая неделя» выберите день и введите занятия. Одно занятие имеет
   один ID, несколько групп и, при необходимости, несколько преподавателей.
   Длительность — число последовательных слотов; это не сумма часов подгрупп.
4. Переключайте виды классов, групп, учителей и кабинетов. Перетащите нужную
   карточку на другой урок; подсветка и подсказка показывают допустимость. Если в
   слоте несколько карточек, мышь выбирает конкретную полосу подгруппы. Общий
   урок отображается одной карточкой на всю ячейку, две подгруппы не расширяют слот.
   Номер урока можно изменить в форме без мыши. Ctrl+Z / Ctrl+Y отменяют и повторяют
   редакторские изменения до следующей посторонней записи проекта.
5. Меню «Генерация» размещает введённый набор занятий по дням и урокам с сохранением
   идентичности, преподавателей, длительности и закреплений. Это генерация по уже
   введённым занятиям, отдельного мастера учебных планов пока нет.
6. Выберите конкретную дату. «Отсутствие» задаёт преподавателя, диапазон дат и
   необязательный список номеров уроков. Диагнозы не записываются.
7. «Рассчитать A / B»: A сохраняет номера уроков, B допускает перестановки дня.
   Расчёт идёт в отдельном процессе, его можно отменить. Сравните метрики и список
   до/после. Выбранный результат становится **черновиком**, базовая неделя неизменна.
   Для непроведённых занятий создание обязательств включается явно по правилу школы.
8. Укажите дневные/недельные лимиты и основание школьных правил в справочниках.
   Подтверждение правил требует права утверждения. Программа не подставляет
   неподтверждённые универсальные нормативы.
9. «Проверить» → «Утвердить» → печать/PDF. «Публикация» формирует локальный выпуск
   и очередь, **внешняя отправка пока не реализована**. Изменение дня делает старую
   очередь неактуальной. В очереди нет ложных отметок об отправке.
10. «Невыполненные занятия»: назначьте восполнение на будущую дату в свободный слот.
    После утверждения этой даты подтвердите фактическое проведение — обязательство
    закроется ровно один раз.

## Доступ, данные и копии

Администратор управляет справочниками, пользователями и публикациями. Составитель
редактирует/рассчитывает, диспетчер дополнительно утверждает, роль «Просмотр» не
вносит изменения. Разрешения проверяются сервисами. После 15 минут бездействия —
блокировка с повторным входом. Полноценные ограничения просмотра конкретным
учителем/классом пока не реализованы; роль «Просмотр» видит школьный проект целиком.

По умолчанию данные находятся в `%LOCALAPPDATA%\TimeLabs` на Windows, в
`~/.local/share/TimeLabs` на Linux, **отдельно от программы**. `TIMELABS_DATA_DIR`
переопределяет каталог. Несколько сотрудников с локальными учётными записями
программы работают по очереди в одном профиле Windows. Для общей папки разных
Windows-профилей администратор должен отдельно настроить локальный каталог
ProgramData и его ACL. Не размещайте рабочую БД на сетевом диске.

Вторая копия приложения с тем же каталогом данных блокируется через QLockFile;
записи дополнительно защищены оптимистической проверкой версии и транзакцией.
Пароли хешируются Argon2id. Полная резервная `.db` содержит хеши учётных записей,
поэтому защищайте копии так же, как рабочую базу. Переносимый проект `.tlabs`
содержит данные, редакции и историю с именами авторов, **без таблицы пользователей,
паролей и настроек аутентификации**. SHA-256 проверяет повреждение, но не является
цифровой подписью доверенного отправителя. Импорт требует повторного утверждения.

«Резервная копия» использует SQLite Backup API и integrity_check. Копия также
создаётся перед заменой проекта или импортом. Рабочую WAL-БД вручную не копируйте.
Восстановление при закрытой программе (из исходников):

```powershell
.venv\Scripts\python.exe -m timelabs.maintenance C:\Backup\school.db --login admin
```

Будет запрошен текущий пароль, сохранена копия до восстановления и проверена
целостность исходника. После восстановления действуют учётные записи из копии.
Для полностью утраченной установки сначала создайте пустую локальную установку с
администратором и затем выполните восстановление.

## Excel

Экспорт базовой недели создаёт XLSX со справочными листами кодов. Импорт этого
формата имеет предварительную проверку и требует подтверждения. Спорные/неизвестные
коды и пересечения блокируют запись. Произвольные сложные школьные таблицы,
цвета и исходная 10-листная книга требуют отдельного адаптера и сверки; похожие
фамилии автоматически не объединяются. Правила колонок видны в экспортном шаблоне.

## Проверки и сборка

```bash
QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest -q
```

На Windows выполните `scripts/build-windows.ps1`. Он устанавливает фиксированные
версии, запускает тесты и собирает папку standalone PyInstaller вместе с архивом
и SHA-256. На целевом ПК Python и интернет не нужны. Workflow
`.github/workflows/windows.yml` выполняет этот сценарий на Windows и сохраняет
артефакт. Он добавлен в исходники, но его запуск/успех не подтверждены этой сессией.
Для выпуска необходимы испытания на чистом Windows 11 с принтером, проверка Qt/OR-Tools
DLL, лицензий зависимостей и автономного обновления. Установщик и подпись пока не готовы.

Уточнённую школьную книгу и список кабинетов можно открыть через «Проект →
Школьная книга и кабинеты». Это отдельная сверка с компактным недельным обзором,
сохранением происхождения всех строк и протоколом вопросов; неподтверждённые
назначения автоматически в рабочую базу не переносятся.
